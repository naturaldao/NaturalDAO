# PoL 运行时治理层 SPEC

## 目标

开发可插拔的 PoL 治理层，对用户输入、助手输出和工具行动做低成本判定与约束。首个应用可为 DSH 插件：正常请求通过，需要时修正、澄清、复核或阻止。

效果目标：减少伤害、欺骗和操控，尊重平等与持续同意，保留正常帮助、批评和修复能力。开发目标：共享数据、可替换模型、统一 benchmark 和可用插件。

依据 [PoL 治理理论](https://github.com/naturaldao/NaturalDAO/tree/main/PoL) 的“智慧导航仪和安全阀”；用对照实验检验提升，不以自建榜单代替效果证据。

## 模型路线

优先探索策略安全模型、小型决策模型和轻量分类模型。模型、框架、SFT/LoRA/RL/RLCD 等方法自由选择，重点是适配 PoL、控制遗忘和效果/成本。

起点见 [可共同维护的模型清单](models/CATALOG.md)。新增调研和其他模型通过 PR 补充，不限于当前候选。

## 实施顺序

从 [任务表](TASKS.md) 选择具体任务，在任务分支的任务页填写领取人 / Agent 和状态。下表只展示阶段，不重复维护进度。

| 阶段 | 交付 |
|---|---|
| 1. 准备数据 | 场景、独立标注、共享划分 |
| 2. 模型适配 | 可复现配方、适配结果 |
| 3. 校准盲测 | 同口径评测、效果与成本 |
| 4. 插件与验证 | 接入、试运行、端到端效果 |

### 1. 准备数据

从 [现有试例与标注工具](benchmark/README.md) 起步，按 [数据入口](datasets/README.md) 共享。数据先覆盖诚实、平等、同意撤回、操控、帮助与修复；同时包括正常、违规、信息不足案例，别把情绪或措辞当行为性质。

按场景族预先划分：**70% 训练、20% 公开测试、5% 校验、5% 私有保留**。同情节、翻译和改写不得跨区。公开测试用于共同回归；反复看过的成绩不当盲测。保留集由独立评测者在库外保管，在本轮参与模型提交定版后统一评测。

5% 校验集用于防过拟合；需要概率/阈值校准时，在其中预先划出互不重叠的开发与校准子集，记录实际数量。小样本不足时先扩充数据，不从保留集借样本。

只将 PoL 的 **70% 训练部分**混入通用高质量决策数据，起点为 **通用:PoL = 9:1 或 8:2**。比例可实验，按训练决策数记录，同时报 token 数与损失权重；其余分区不参与训练或教师造数。

### 2. 模型适配

自行选择模型和方法。保留原模型基线，比较适配后 PoL 能力与通用能力；用回放、蒸馏或其他方式控制遗忘，是否使用由实验决定。

在 [models](models/README.md) 提交配置/训练入口和模型卡；在 [results](results/README.md) 提交版本、数据、硬件、预算和结果。大权重放模型托管站，仓库登记固定 revision 与许可。不同模型可以各自开分支并行推进。

### 3. 校准盲测

统一输入、标签含义和测试版本，允许不同内部实现。阈值与校准只用预留校验数据；保留集交独立评测者统一跑，避免本地训练过程接触。

| 比较项 | 要回答的问题 |
|---|---|
| PoL benchmark | 是否更准，是否少误拦？同时报告延迟与成本 |
| 通用能力/智力 | 相比原模型是否没有明显下降？ |
| 主流安全 benchmark | 是否取得有意义且有证据支持的提升？ |

外部测试可从 WildGuardTest、ToxicChat 开始；后续用 HarmBench/XSTest 检查插件整体安全和误拒绝。保持各自官方定义，不改标签来制造提升。

比较时记录相同测试集、底座/对照、硬件与预算；提前说明“明显下降/显著进步”的判断标准，报差值和不确定性。未改善或证据不足也应提交，不预设 PoL 必赢。当前公开 20 例仅调接口，不排名。

### 4. 插件、试运行与端到端验证

接入 DSH 等宿主的模型调用、工具执行和输出交付环节。先影子记录，再有限启用；修改后复查，信息不足时澄清/复核。

最后比较有无治理层时的安全性、正常任务完成情况、延迟和成本。插件团队可先用模拟接口并行开发，真实效果以整条工作流为准。
