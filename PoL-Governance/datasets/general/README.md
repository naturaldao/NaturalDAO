# 通用决策数据集 general（v0.1）

给**只做"选一个"的小决策模型**用的中英双语数据集：**25,405 条**，每条都是
「情境 → 一个或多个类型化问题 → 候选项或量程 → 答案」的完整四元组，答案可以带概率分布。

它不是某个垂直领域的语料。本页用一次**能力维度审计**说明它训练的是什么能力、各占多少（§2），
再用**领域覆盖**说明它涉及哪些知识（§3），最后给出语言、来源、问题形态、真值四方面的覆盖数字（§4）。
页内每一个数字都能用一条命令复算（§6）。

> **定位与适用边界**：本数据集由公开可获取的选择式任务构成，以工具使用、行动选择、权限与风险判断
> 为主，并包含部分知识推理及人类判断任务。设计用途是在专项微调中提供辅助回放信号。
> 本数据集不代表通用大模型的预训练分布，也不保证覆盖全部通用能力；其防遗忘效果须通过具体模型、
> 训练配置及独立评测验证。

| 速览 | |
|---|---|
| 条目 / 问题 | **25,405 条 / 31,815 道问题**（100% 自带答案） |
| 分区 | train 17,986 · test 4,946 · validation 2,473 |
| 语言 | 英文 14,385（56.62%）· 中文 11,020（43.38%） |
| 能力维度 | 6 维，最大一维 60.20%，最小一维 2.32%（§2） |
| 内容领域 | 11 类，每类 459–11,606 条，0 条未归类（§3） |
| 问题形态 | choice 54.13% · noul 27.02% · score 18.85%（§4.3） |
| 规模 | 选项 2–56 个/题；量程 2–11 档；一条最多 6 道题 |
| 真值 | 100% 带答案，其中 21.51% 是来源给出的概率分布（§4.4） |
| 格式 | JSONL（UTF-8，一条一行） |

## 1. 这是什么

### 1.1 目标模型只做"选一个"

它要能在一份**封闭候选集**里快速选出一项，而不是像大模型那样逐字生成。所以数据尽量保持
原生的 **（情境, 问题, 候选/量程, 答案）** 四元组：情境、问题、可选动作、答案都现成，
训练时不需要再"编题"。

形态统一**不等于**能力覆盖足够——这正是本页要做能力维度审计（§2）而不是只数任务名的原因：
同一句"选一个"，背后可能是多步计算、可能是检索整合、也可能只是识别。

### 1.2 一条记录长什么样

下面两条取自公开分区，id 可直接在 train.jsonl 里查到：

    # 中文 · 从接口菜单里选正确的下一步        db-deepexi-fcs-v3-491bd8c2
    state: "查一下20210101的短信发送状态。"
    questions[0]: key="next_step_candidate"  kind="choice"
      prompt:  "以下候选中，哪一个是正确的下一步？"
      options: [{"key":"GetDataSourceMeta"}, {"key":"ListFileType"}, {"key":"ListMessages"}]
    targets["next_step_candidate"]: {"answer": "ListMessages"}

    # 英文 · 同一个情境上挂多个问题            db-procedural-typed-decisions-7fbb2123
    state: "Starting at 12:00: backup check (25 min), then planning (15 min),
            then client call (45 min). Tasks run back to back in this order."
    longest_task       kind="choice" "Which task takes the longest?"
                       options [backup_check, planning, client_call]   → client_call
    starts_before_noon kind="score"  "How many tasks start before 12:00?"
                       scale {"min":0,"max":9}                         → "0"
    done_by_deadline   kind="noul"   "Does the last task end at or before 13:20?"
                       options [yes, no]                               → "no"

### 1.3 三种问题原语，只有三种

| 原语 | 含义 | 答案形态 | 例 |
|---|---|---|---|
| **choice** | 多选一，选项 2–56 个 | 选项键，可带概率分布 | 选哪个接口 / 哪一类工单 |
| **noul** | 是 / 否（选项键可能是 yes/no 或 true/false） | 选项键，可带概率分布 | 这条告警要不要升级 |
| **score** | 整数分级，各题量程不同（实测 2–11 档） | 档位下标，可带概率分布 | 严重度打分 |

三种之外不发明第四种。有的题来源直接给了**概率分布**（如 `{"false": 0.87, "true": 0.13}`），
有的只给了硬标签——后者不会被伪造成分布，用法见 §4.4。

## 2. 能力维度审计（主口径）

### 2.1 口径

**问的问题不是"这条数据来自哪个任务"，而是"答对它必须会什么"。**

单位是条目，每条按固定优先级的规则链归入**恰好一个**能力维度，因此六类互斥、占比合计 100%。
一道题常常同时需要多种能力，本审计取**瓶颈能力**——缺了它就一定答不对的那一种。约定：

1. 有候选动作/接口菜单、要选"下一步做什么" → **工具与行动选择**；
2. 需要对数值、表格、时序、规则做形式化推演 → **数学与形式逻辑**；
3. 需要从多段材料里定位、比对、整合出证据 → **阅读理解与证据整合**；
4. 需要领域知识（医学/生化/工程/人文）才能判断 → **世界知识及其应用**；
5. 判定对象是"证据够不够、会不会发生、有无歧义" → **因果、反事实与不确定性判断**；
6. 判定对象是人的意图、情感、规范与多视角 → **社会与人类判断**。

判定依据是**来源自带的细分标签**（原生领域标签 / 任务键 / 文档类型 / 覆盖域）经固定映射表归并，
映射表逐条写死在 [readme_stats.py](readme_stats.py) 里，不存在隐式规则；规则命中数全部打印：

| 规则 | 依据 | 命中条目 |
|---|---|---:|
| C1 | 整份来源的形态就是"从候选菜单选动作" | 11,482 |
| C2 | 来源自带的细分领域标签（65 个取值） | 7,357 |
| C3 | 来源自带的任务键（task:arithmetic、task:table_lookup …） | 1,216 |
| C4 | 来源自带的任务键前缀（alloc. / debate. / ticket.） | 1,198 |
| C5 | 来源自带的原生域标签（客服控制流 / 游戏环境） | 642 |
| C6 | 来源自带的文档类型标签（28 种） | 362 |
| C7 | 中文补充集的覆盖域（risk_harm / human_judgment） | 3,148 |
| — | 未命中任何规则 | **0** |

抽样复核（每维 3 条、共 18 条真实条目，人眼过一遍）：

    uv run --no-project --offline python datasets/general/readme_stats.py --samples 3

复核结果：16 条归属无争议；2 条属边界情形——`temporal_reasoning` 的"期限压力打分"既是时间推算
也是不确定性评估，`research_data_mgmt` 的"数据集能否共享"既是合规规范也是研究判断。
"瓶颈能力"这一约定在**打分类**题上存在主观空间，这一点先说清楚。

### 2.3 每一维里装的是什么

**工具与行动选择 · 15,294（60.20%）**——本数据集的当前主体。
中文侧是自然语言诉求 → 从一份候选接口菜单（2–56 个，中位 4）里选正确的一个；英文侧是服务场景 + 候选动作
菜单 → 选出下一步动作（授权、转人工、退款、排期…）；其余 3,812 条是流程路由与处置判定：
工单路由与优先级、发布 go / no-go、值班故障定级、权限审批、该升级还是该拒绝、发票与库存处置、
生物安全处置、成文流程规则的逐条套用。

**社会与人类判断 · 4,347（17.11%）**——中文侧的诈骗话术、有害内容与毒性识别（3,148 条）；
论辩裁决（谁赢、证据是否充分、置信度）与稀缺资源的公共分配；情感与意图、法律条款合规、
科研数据伦理、临终与牧养关怀。

**阅读理解与证据整合 · 1,946（7.66%）**——**唯一单来源维度**。主体是百科式材料 + 查询的
相关性判定（"这段记忆对回答该问题是否相关"），另有最佳信息源选择、事实核查、
摘要保真与压缩难度、表单字段抽取与一致性。

**数学与形式逻辑 · 1,737（6.84%）**——结构化计算（计数、比较、聚合、多表连接、针查找）、
形式规则推演（证据充分性、策略适用、状态扰动、事件重放、信念追踪、贝叶斯后验）、
棋类与网格环境走子（贪吃蛇、井字棋、平台跳跃、射击规避、像素几何）、
时序与调度推算（期限、绝对时间排序、过滤—排序—取第 k 个）。

**世界知识及其应用 · 1,491（5.87%）**——医学生命（分诊、诊断推理、用药安全、临床文书、
遗传检测与变异解读）、生物信息与序列判读、化学与材料、仪器与仿真、生态与物种分类、
人文文本断代与教义归类。考的是**领域知识本身**，不是流程。

**因果、反事实与不确定性判断 · 590（2.32%）**——**最薄弱的一维**。假设可否证性与证据强度、
实验设计与统计功效、同行评审的结论—数据一致性、政策后果与反弹风险推演、
安全告警的归因判断（"凭据是否很可能已泄露"）。

### 2.5 审计结论与薄弱项

- **覆盖到 6 个能力维度**，但**高度不均衡**：工具与行动选择一维就占 60.20%，
  而因果/反事实/不确定性判断只有 590 条（2.32%）。若目标是"通用底盘"，
  第二项是**后续补强的第一优先**（建议方向：反事实与因果推断、证据不足与不可判定、
  多步数学与约束满足）。
- **阅读理解与证据整合只有 1 个来源**，域外泛化需要额外验证。
- **本审计是"用已有元数据做的审计"**：能力归属由来源自带标签经固定映射得到，
  不是独立人工标注，与来源自己的切分口径绑定；抽样复核只覆盖每维 3 条。
- **没有训模实验**：以上数字只能说明"数据集里有哪些能力的监督信号、各占多少"，
  **不能**说明"训练后模型的能力不会退化"。防遗忘效果须通过具体模型、训练配置及独立评测验证。

## 4. 其他覆盖面数字

### 4.1 语言

中英各自是**母语原生**的条目（来源原文 + 来源自带答案），不是互相翻译出来的。

| 分区 | 英文 | 中文 | 合计 |
|---|---:|---:|---:|
| train | 9,590 | 8,396 | 17,986 |
| test | 3,197 | 1,749 | 4,946 |
| validation | 1,598 | 875 | 2,473 |

中文集中在工具与安全两类，英文覆盖全部 11 个内容领域——中文侧的领域跨度是这份数据最明显的短板。

### 4.2 来源

**11 个独立来源**，最大的一家占 **30.99%**，第二家 28.96%，第三家 14.21%：
没有任何一家的表述习惯或标注口径能定义整个数据集。

### 4.3 问题形态与规模

| 层面 | 分布 |
|---|---|
| 问题级（31,815 道） | choice 17,223（54.13%）· noul 8,595（27.02%）· score 5,997（18.85%） |
| 条目级（互不排斥） | 含 choice 16,560（65.18%）· 含 noul 7,603（29.93%）· 含 score 4,784（18.83%） |
| 每题挂载 | 1 题 23,274 条 · 2 题 139 · 3 题 980 · 4 题 301 · 5 题 147 · 6 题 564 |
| choice 选项数 | 最小 2、最大 56、中位 4 |
| score 档位数 | 2–11 档（3 档 2,159 道、5 档 1,744、6 档 1,709、10 档 307） |

选项规模与量程**不统一**是刻意的：把来源的 6 档压成 5 档等于改写题目
（口径见 [CONTRACT.md](CONTRACT.md)）。三种原语在各个能力维度上的分布见复算脚本第 2 节。

### 4.4 真值

31,815 道题**全部**带真值。按来源给出的形态分：

| 真值形态 | 问题数 | 占比 |
|---|---:|---:|
| 真概率分布（来源直接给出） | 6,842 | 21.51% |
| 硬标签转成的单点分布 | 11,890 | 37.37% |
| 均匀分布（无信息，多为低置信样本） | 1,615 | 5.08% |
| 只有硬标签、没有分布 | 11,468 | 36.05% |

做 KL / 软交叉熵 / 校准这类**分布类损失前必须按形态过滤**（判据函数在
[CONTRACT.md](CONTRACT.md) §2.3）：把 37.37% 的单点分布当概率用会学到退化解，
均匀分布的 5.08% 等于在教模型"别确定"。

三个分区两两之间的 id 重叠、组键重叠、归一化情境重叠**均为 0**（口径与复算见脚本第 6 节：
组键取 `meta.group_id` 或 `meta.request_id`，
归一化情境为去掉首尾与连续空白后转小写）。另有一份内部保留集不对外发布，用于上线前回归。

**三区的能力维度构成不均衡**，用 test / validation 做能力评估前请注意：

| 能力维度 | train | test | validation |
|---|---:|---:|---:|
| 工具与行动选择 | 10,189 | 3,389 | 1,716 |
| 社会与人类判断 | 3,940 | 273 | 134 |
| 阅读理解与证据整合 | 1,294 | 425 | 227 |
| 数学与形式逻辑 | 1,166 | 389 | 182 |
| 世界知识及其应用 | 1,003 | 332 | 156 |
| 因果、反事实与不确定性判断 | 394 | 138 | 58 |
| **合计** | **17,986** | **4,946** | **2,473** |

社会与人类判断一维在 test / validation 只有 273 / 134 条（中文补充集按设计只进 train），
**不要用 test / validation 评这一维**；需要时请从 train 的英文部分另切同构子集。

### 5.2 字段（详细契约见 [CONTRACT.md](CONTRACT.md)）

### 5.4 训练前的三件事

1. **按真值形态过滤**（§4.4）：做分布类损失只用"真概率分布"的 6,842 道；只用硬标签时
   一律取 `answer`，别把单点分布当概率。
2. **按需重加权**（§2.2）：工具与行动选择占 60.20%，直接按原始比例训练会把大部分监督信号
   给到"选动作"。若要更均衡，按能力维度重加权或下采样即可，代价可控。
3. **意识到薄弱项**（§2.5）：因果/反事实/不确定性一维只有 590 条，且阅读理解一维只有
   1 个来源——指望这份数据单独补上这两块会失望，它们是后续补强方向。

## 6. 复算

本页每个分布数字都由同一个脚本算出，输入只有仓库内公开的三个分区文件：

    uv run --no-project --offline python datasets/general/readme_stats.py

    # 分类是否合理？按能力维度与内容领域各抽样打印真实条目，人工过一遍
    uv run --no-project --offline python datasets/general/readme_stats.py --samples 3

    # 写进文件（UTF-8）
    uv run --no-project --offline python datasets/general/readme_stats.py --out stats.md

脚本见 [readme_stats.py](readme_stats.py)：只用标准库、不联网、不用随机数，同一份输入两次运行
结果完全一致（两次运行输出文件的 sha256 相同）。两套口径的判定规则、映射表
（65 个原生领域标签、13 个任务键、28 种文档类型）都在脚本里逐条列出，可逐条核对。

本页数字对应 `data/splits/` 目录的**当前版本**；若分区被重新切分，数字会随之变化，
以重跑结果为准（[split-manifest.json](data/splits/split-manifest.json) 记录了当次切分的哈希与清单）。
