Kev-4B 前后对照评测：原版与 POL2 score-v2 M10

PoL-Governance · Session B 独立评测 · 2026-10-28 · 单文件自包含报告

微调后的模型在准确率上略有提升，但在概率校准、风险控制和自动处置能力上明显变差；第三方一致性基准上的分数上升，但那一指标不是准确率，也不能作为能力提升的证据。

数据集模型与训练主结果校准与风险稳健性外部对标经验与失败复现

评测数据集：只用了私有保留集

本文所有主结果只使用一份事先冻结的私有保留集（模型训练和选型时都看不到它）。它包含 6,541 个情境条目和 7,990 道封闭式问题；问题分为三类：choice（从候选中选一个）5,501 道、noul（是/否）1,446 道、score（按等级打分）1,043 道。全部为英文。

评测时每道题独立计分。由于模型只在有限长度的输入上有已验证能力，最终进入比较的是 7,347 道题（来自 6,299 个条目）——这是本文所有表格和图表的分母；其余题目不属于共同可评测范围，不参与任何数字。被评测子集的三类题为 choice 5,194 / noul 1,221 / score 932。

两个领域：决策机制（decision_mechanics）2,386 个条目、知识推理（knowledge_reasoning）4,155 个条目。输入文本长度（字符）中位数 312，90 分位 643，最长 13,972；按 token 计，已评测题目的状态长度中位数 74、90 分位 165、最大 383。选项数从 2 到 68 不等。

读法：输入多为几百字符的短文本，少数长文档；选项数大部分在 2–8 之间，但也有少量几十个选项的题目——后一类对准确率影响很大，后文会按选项数分层。
数据边界：私有保留集只在本机隔离环境使用，只导出聚合数字，评测后删除临时副本；已核对它与微调模型训练数据的重叠：重叠为零。

模型与训练配置

被测模型是 Kev：把决策问题当作“在候选选项之间做指针选择”的小模型族，底座 Qwen3.5-4B-Base；公开代码固定在 commit 2074cc44。比较同一架构的两个权重：

  • 原版 Kev-4B：jaredpalmer/kev-4b@v1.0，Hub commit 6cfce5c2，随权重发布的温度为 2.41（Kev 作者在自家开发集上拟合）。
  • 微调版（M10）：协作者用 POL2 score-v2 数据在原版上继续训练得到的 LoRA + pointer head，GitHub Release pol2-score-v2-v1.0.0。本文报告三个随机种子：seed-43（主）、seed-17、seed-29。三个 seed 都记录温度 1.0（未拟合）。

披露一个选择问题：seed-43 是在看到三个 seed 的既有结果之后才被选为“默认推荐版本”的。因此它的数字属于事后选择（post-selection）的探索性结果，不是事先预注册的确认性证据；seed-17/29 的全部结果同样列出，三个 seed 不是集成（ensemble）。

读法：横轴 0 = 与原版相同；点在 0 右侧表示数值更大。准确率右侧为好，Brier/NLL 右侧为差。seed-43 的准确率区间整体在 0 右侧，Brier/NLL 区间也整体在 0 右侧——即“更准一点，但概率明显更差”。

配对统计：差异是不是真的？

同一道题被两个模型各答一次，因此正确/错误是可配对的。我们做三件事：①用配对 cluster bootstrap（按条目/集团簇重抽样 2,000 次）估计差值的 95% 区间；②对准确率用 McNemar 精确检验（只比较两个模型答案不一致的题）；③对 Brier/NLL 用簇符号翻转置换检验（2,000 次）得到 p 值，并用 Holm 方法控制三个 seed 的多重比较。下表同时给出效应量与检验结果。

怎么读：“McNemar p”回答“准确率差异是否可能是巧合”，p 越小越不像巧合；“Holm p”是对三个 seed 同时比较后的校正值。Brier/NLL 的置换 p 同理。注意：统计显著不等于实际重要——seed-43 准确率只高 0.95 个百分点，但 Brier 高 0.073、NLL 高 0.70，后者的实际影响远大于前者。
读法：灰色柱是 2,000 次重抽样得到的差值分布；黑色实线是点估计，虚线是 95% 区间。分布整体不跨 0（准确率在右、Brier/NLL 在左）说明差异稳定；但三者尺度不同，要看相对大小而非绝对高度。
读法：红线落在灰色分布的极端尾部（p<0.01），说明观察到的准确率与 Brier 差异不太可能只是抽样巧合。置换只检验“是否有差异”，不说明差异有多大——效应量看前面的表和森林图。

读法：本题库有 7,347 道题，95% 区间半宽约 ±1.2 个百分点；若只有 200 道题，半宽会超过 ±7 个百分点——这就是小样本无法给相近模型排名的原因。

校准与自动处置风险

决策模型不只要答对，还要知道自己有多确定。如果模型说“95% 确定”时实际只有 60% 正确，那么按置信度自动放行就会出错。这一节专门评估“概率是否可信”，以及它对自动处置的影响。这是本报告与只报准确率的评测最重要的区别。

指标怎么算怎么读
Brier把每个选项的概率与“正确答案为 1、其余为 0”的目标做平方差后求和，再对题目取平均综合衡量概率误差；越低越好。它对罕见类别的错误惩罚较重
NLL正确答案所获概率的负对数，再取平均对“自信地答错”惩罚极大；越低越好
ECE-10 / ECE-15把置信度分 10 / 15 个等宽箱，比较每箱“平均置信度”与“实际正确率”，按箱内题数加权0 为完全校准；0.02 可视为很校准，0.2 表示置信度严重偏离实际正确率。两套分箱结果并列，避免一种分箱的偶然性
automation @5%按置信度从高到低接收题目，在“接收集错误率 ≤5%”约束下，最多能自动处置的题目比例越高越好，但这是本样本上的经验值，不是真实部署的错误保证；同时要报接收题数与接收集错误率
AURC风险-覆盖曲线（横轴覆盖率、纵轴错误率）下方面积越低越好，衡量“用置信度排序”的整体质量

读法：同样的过度自信模式；这也是 noul 准确率下降与 Brier 变差的主要来源。
读法：原版的校准误差小、区分能力也较好；微调版校准误差明显变大。

稳健性检查（辅助结论）

我们把同一道题换一种问法再问一次，检查答案是否稳定，共两类：选项顺序打乱（600 道 choice 题，顺序随机重排）与拆题单独提问（把一次请求里的多道题拆成独立请求）。这些检查不直接等于“是否降智”，但能说明模型对无关变化的敏感程度；结论只作辅助。

选项顺序打乱（n=600）：Kev-4B original：6.1% 平均最大概率变化、10.2% 翻转率；M10 seed-43：10.3% 平均最大概率变化、11.3% 翻转率；M10 seed-17：10.0% 平均最大概率变化、11.2% 翻转率；M10 seed-29：9.3% 平均最大概率变化、10.7% 翻转率。 拆题单独提问（n=1916）：Kev-4B original：0.2% 平均最大概率变化、0.2% 翻转率；M10 seed-43：0.3% 平均最大概率变化、0.5% 翻转率；M10 seed-17：0.3% 平均最大概率变化、0.3% 翻转率；M10 seed-29：0.3% 平均最大概率变化、0.4% 翻转率。

读法：选项顺序打乱时，微调三个 seed 的平均概率变化（约 9–10 个百分点）高于原版（6.1 个百分点），答案翻转率也从 10.2% 升到 10.7–11.3%；拆题单独提问的影响对所有模型都很小（平均变化 ≤0.35 个百分点）。也就是说，微调让模型对“选项怎么排”更敏感，而对“一次问几道题”不敏感——这与“更依赖表面选项模式”的解释一致，但不构成能力结论。

读法：曲线越靠左下越稳定。左图（选项顺序）微调版整体右移，右图（拆题）几乎重合。

外部对标：JevBench 与其它榜单

JevBench 是什么：一个第三方的“决策一致性”基准（Chen Feng，Queen's University Belfast；与 TypeSafe 无关），不考知识量，而是考模型的概率与选择是否满足 50 条一致性关系（例如同义改写后答案不变、互斥选项概率相加、选项顺序不改变相对概率）。它没有金标答案，因此衡量的是 coherence，不是 accuracy。我们跑的是 mini 版本（1,240 次请求），这也是官方榜单的默认口径。

读法：越靠外越好。五个维度分别为 REP（表述不变性）、BAT（批次独立性）、MEA（概率测度）、LOG（逻辑顺序）、CHO（选项集合条件）。两条实线是我们的本地复跑；虚线是官方榜上的 Kev-4B 数值。

微调后的位置：seed-43 相对官方 Kev-4B 的 JevBench 差值为 +8.99 分（z = 5.80，p = 6.52e-09），在统计上明显更高；若放在已公布榜单里，大致位于前列。但这是 coherence 指标，且我们没有计算它的 accuracy（需要第三方金标），所以只能说“一致性更好”，不能据此宣称“更准”或“排名更高”。

官方 Jev API 的成绩在哪：JevBench 的公开榜单里没有 TypeSafe Jev 托管 API 的条目（榜上只有 21 个开源模型与 4 个 toy/random/uniform 参考）；能查到的官方 Jev 数字来自 Kev 作者的另一个对比表（Decision Index：Jev 54.0、Kev-4B 38.0、Kev-27B 52.3，accuracy 型指标），那是不同基准、不同指标，不能与本文的 coherence 分数并列。本文的官方对照只用 JevBench 榜单上的 Kev-4B 一行。

微调后的 seed-43 在 JevBench-mini 上为 80.91（95% CI [78.7, 83.2]），比本地原版高 8.7 分，提升主要来自 MEA（概率测度）与 LOG（逻辑一致性），CHO（选项集合）略降。这个结果说明微调改变了模型的一致性行为，但不能替代准确率与校准结论：同一批权重在私有保留集上的准确率只高 0.95 个百分点，校准却明显变差。两项结果共同指向“能力结构改变”，而不是“整体变强”。

运行成本、失败与经验

成本

评测在一张 AMD Radeon RX 7900 XT（20 GB，WSL2 + ROCm 7.2.1）上完成，单卡串行。四个权重各评测 9,052 条请求（含变体），每个约 16–17 分钟；每道题的中位延迟 83.8 ms（原版）到 77.7 ms（seed-43），p95 约 0.34–0.36 s。CPU（Ryzen 5700X，fp32）只用于公开样本的冒烟测试，不是性能基准。GPU 显存峰值未测（WSL 无相应监控模块）。

我们遵守了项目 GPU 纪律：只在允许时段启动单卡任务，运行前后检查系统事件日志（Kernel-Power/BugCheck/WHEA 无异常）。

读法：四个权重延迟相差不大（中位约 78–84 ms，p95 约 0.34–0.36 s）。延迟不是本次结论的区分因素。

失败与修复（都发生在报告数字定稿之前）

  1. 20 GB 显存装不下超长题目的 attention。首轮完整评测在一条输入约 4.7k token 的题上触发 HIP OOM（eager attention 的 L×L 缓冲需要 4 GB）。处置：按硬件可执行性把 5 个条目（14 道题）单列为“本机不可评测”，其余题目重跑成功（0 拒绝）；这些条目没有进入任何数字。
  2. JevBench 的请求缓存会跨模型复用。jevbench 0.1.0 的缓存键不包含被评测的 checkpoint，单独加 --no-cache 仍会返回上一模型的缓存响应，导致两个模型分数逐位相同。处置：每个模型使用全新缓存目录，并用服务端日志的 POST 计数（各 1,442 次）确认请求真的落到对应模型上，然后重跑。
  3. 依赖版本超出上游声明。Kev 声明 torch<2.9，本机是 2.9.1+rocm7.2.1。我们记录了完整环境并全流程实测通过；这项偏离已写入限制，不能把本报告数字与官方 fp32 结果直接等同。

可迁移的经验

  • 报告“更准”之前先问“概率能不能信”：本次微调的准确率提升 0.95 个百分点，但 ECE 从 0.025 升到 0.21，实际部署含义完全相反。
  • 配对比较比独立比较灵敏得多：同一道题上逐题比较能把“谁更好”的区间缩到 ±1 个百分点量级。
  • 保留集只能评一次、不能用于任何选择；事后选出的 seed 必须明确标注，否则结论会被高估。
  • 复现细节（固定 revision、固定缓存、记录环境与失败）比多跑一个模型更重要。

指标与统计词典 / 复现

指标定义

ACC（准确率） = 答对题数 / 总题数。
Brier = (1/N) Σi Σk (pik − yik)²，其中 y 为 one-hot 金标；0 最好。
NLL = −(1/N) Σi log pi,yi，即正确答案概率的负对数均值；越低越好，对自信答错惩罚大。
ECE = Σbins (nb/N) · |accb − confb|；coverage@5%：按置信度降序接收、在接收集经验错误率 ≤5% 时能接收的最大比例；AURC 为风险-覆盖曲线下面积。

统计方法

配对 cluster bootstrap：以条目/情境簇为重抽样单位（同一条目的多道题一起抽），重抽样 2,000 次估计差值区间，处理同源题目的相关性。McNemar 精确检验：只用“一个对一个错”的题做二项检验，适合配对准确率。置换检验：在“两个模型可互换”的零假设下随机翻转每个簇的差值符号，得到 p 值。Holm 校正：对三个 seed 的多重比较控制族错误率。Wilson 区间：单模型比例的 95% 区间，适合小比例与中等样本。

本文做过的与没做的事

  • 做过：固定数据与权重 revision；对私有保留集只导出聚合；配对统计、校准与风险分析；JevBench 本地复跑；与官方榜的误差范围内对照。
  • 没做：多 seed 重新训练；在保留集上拟合温度或调阈值；语义层面的训练数据去重；JevBench 的 accuracy（需第三方金标）；榜单提交。
