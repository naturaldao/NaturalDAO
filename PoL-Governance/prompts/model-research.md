# Research Agent Prompt：PoL 治理层模型选型

请执行一次深入、可核查的模型调研，最终推荐 **3–5 个能够实际训练和本地部署的候选**。报告使用中文，注明调研截止日期。你可以推翻已有排名；不要为了凑数量降低硬门槛。

## 任务背景与目标

我们要构建基于 Proof of Love（PoL）的 AI **运行时治理层**：在用户输入、助手输出及工具执行前，进行廉价、快速、可校准的判断，必要时请求澄清、指导修改、阻止行动或升级复核。首个产品场景是类似 DSH 的插件。治理模型不需要生成长回答，重点是上下文中的行为判断与约束。

PoL 的目标不只是拦截有害内容，还包括诚实、尊重主体平等与持续同意、避免操控、支持帮助与修复。不能把愤怒、批评、拒绝、不同意见当成违规，不能用温柔措辞掩盖实质伤害，也不能把人贴成“好人/坏人”。最终要检验 PoL 是否在保持有用性和低成本的同时改善治理结果。

先读本项目 [SPEC](../SPEC.md)、[共同维护的模型清单](../models/CATALOG.md)。阅读 [PoL 原文](https://github.com/naturaldao/NaturalDAO/tree/main/PoL)，重点第 1–5 章；PoLEn 是施工中的英译，分歧以中文原文核对。无法访问就说明缺口，不假装已读。

## 调研范围：不要只搜索名字含 Jev 的模型

区分 TypeSafe 官方 Jev、独立 typed-decision 实现、动态标签分类/NLI/对比学习模型、策略可配置的安全模型、普通 LLM logits 基线。不同名字不一定是不同模型；模型别名、量化版和 API 转售渠道不能重复计数。

已有线索仅作起点，全部需要复核最新版本：

- Intern-Decision（internlm）；JevK5（alibiserikbay）；Kev（jaredpalmer）。
- AlexWortega/openjev 与 openjev/openjev 是不同项目，注意权重许可证差异。
- Verdict（heman10x/rlcd-modernbert-151m）；Laya typed-decisions / multilingual；GLiNER2.5-Decide / multi-Decide；CLM-v0.1-8B。
- Shieldstral-1.0-3B 等可按自定义政策判断的安全模型；Qwen3Guard、Llama Guard 等作安全基线。
- SemIf 等推理框架作为通用底座对照，不冒充新模型。

## 到哪里查、怎样判断证据

1. **一手实现**：官方文档、论文、Hugging Face 模型卡/权重文件/历史版本、GitHub 源码/训练脚本/许可证/Issues/Discussions。核对具体 checkpoint、revision、基础模型及其许可证；代码开源不能代替权重许可。
2. **独立实践**：Hugging Face Discussions、Reddit r/LocalLLaMA、Hacker News、相关框架社区、开发者博客，以及公开可访问的 Discord/论坛记录。主动找安装失败、量化退化、长上下文失效、中文误判、显存和校准问题。
3. **X / Twitter**：检索作者发布、第三方复现、批评、后续更正及引用讨论。保存可访问的原帖 URL、日期、作者与具体主张；不可访问就列为未核实线索。不要把搜索摘要、转述、截图或多个转发当作独立验证。
4. 搜索组合包括模型名加 finetune / LoRA / training / CPU / latency / Chinese / calibration / jailbreak / contamination / reproduction；同时搜 typed decision、policy adaptive guard、small decision model、open Jev alternatives 等。记录检索日期与覆盖缺口。

每个核心结论标记：**一手可查 / 独立复现 / 作者自报 / 推断 / 未知**。热度只说明关注度，不能证明精准、可靠或生产成熟。优先寻找反证；对每个入围者至少写一个可能使其出局的具体问题。

## 硬门槛与淘汰规则

| 必须满足 | 检查方法与处理 |
|---|---|
| 可自主部署 | 权重可获得，推理不依赖闭源云 API；只提供 API 的模型退出可训练候选 |
| 可改造、训练与发布 | 核实权重、底座、代码及所需数据许可允许本工程的修改、使用和衍生发布；默认优先宽松许可。非商业限制、许可不明者退出默认名单，另列观察项 |
| 有真实适配路径 | 找到损失函数、可训练参数、数据格式、训练代码入口，或给出足够具体且风险明确的可执行实现；只有“支持 LoRA”宣传不算 |
| 适合 PoL | 能处理中文上下文、条件/例外/同意撤回，支持自定义政策或可训练标签；只能固定敏感词分类者不能承担主判定 |
| 可统一评估 | 能输出可映射的判定/分数，版本可固定，并接受同一数据划分、阈值校准和测试规则 |
| 有现实成本路径 | 提供 CPU 或单消费级 GPU 的部署方案及成本依据；未实测延迟不可写成保证 |

**官方 TypeSafe Jev 当前不支持客户微调/LoRA，不进入最终可训练名单**，可单列外部基线；若新证据改变这一事实，附正式证据再重新判断。权重受限或测试污染不必否定所有研究价值，但不能隐瞒，更不能用被污染榜单支持推荐。

## 每个模型必须回答的问题

- 身份：发布者、首次/最近发布时间、准确模型 ID/revision、参数量、架构、底座、上下文、多语言、代码与权重许可证。
- 判定机制：候选 token、pointer head、NLI、动态分类头、对比投影还是生成式？多问题/多选项是否额外前向？标签措辞/顺序改变会怎样？
- PoL 适配：全参、LoRA/QLoRA、分类头/投影头训练分别是否可用？“已有复现”和“技术推测”分开。是否真正需要 RL，还是 CE/软标签/适当评分损失已足够？
- 训练实践：官方 trainer 与通用框架的兼容性，必须保留的特殊 head、mask、模板和权重文件；一条最小训练—导出—重载路径；预计数据和硬件需求的依据。
- 精准：中文、多轮、模糊上下文、否定、反事实、正常批评、情感操控、同意撤回、prompt injection；不以一般意图分类分数代替这些能力。
- 高效：短/中/长输入、1/8/32 个判断、batch=1 和吞吐批处理；报告硬件、精度、上下文、预填充、冷/热启动、p50/p95、显存/内存、超时率。使用同一工作负载；远程 API 与本地计算分栏。
- 校准与鲁棒：Brier/NLL、可靠性图、风险—覆盖曲线；量化、领域/语言迁移后是否重校准；不要把候选集合 softmax 直接当绝对正确概率。
- 生态：独立复现人数/证据、维护频率、未解决 issue、供应链依赖、版本稳定性。下载量和星标只作背景。
- 污染：公开训练数据、已知测试集进入训练/筛选的情况；对不透明训练语料注明未知，不给“无污染”保证。

## 排序方法与实验建议

先过硬门槛，再做多维比较。默认权重：PoL/中文质量 30%，延迟和资源 25%，训练可复现性 20%，鲁棒与校准 15%，维护及独立证据 10%。许可是门槛，不通过加分补偿。没有可比实测就不给伪精确总分，使用带置信程度的区间/等级及 Pareto 比较，并检查权重变化是否改变推荐。

推荐应覆盖不同可行路线，例如超轻 CPU 筛查、小型深度判定、策略自适应安全模型；这些不是必须凑齐的名额。候选数量最多五个，不足三个合格就如实报告。已有论文成绩、作者演示和你的实测单独列。未获资源预算时不要下载大权重、租 GPU 或调用付费服务；给可执行小实验卡即可。

遵守 SPEC 的公共评估协议：同一 PoL 数据、封存测试、主流安全分类测试和端到端安全/误拒绝测试。提出最能区分候选的最小实验，不能在测试集上挑阈值或改模型。

## 最终交付

1. 一页结论：3–5 个推荐及各自用途、推荐强度、未决风险；明确哪些尚未实测。
2. 完整长名单与淘汰表：模型、去留、原因、支持证据、何种新证据可以改变结论。
3. 入围模型对比表：质量、中文、适配路径/框架、部署成本、许可证、校准、独立证据、适用硬件。
4. 每个入围模型的一张实验卡：固定版本、数据输入、训练步骤、导出方式、验证项目、资源估计、失败退出条件。
5. 反方评估：为什么一个普通小模型/安全模型可能优于 Jev 类；何时不该微调；哪项证据会推翻你的首选。
6. 附证据台账：URL、访问日期、版本、主张、证据等级；论坛/X 的异议及核验结果、访问限制与缺失证据。

结论必须允许“证据不足”。不要以模型名称、作者声望、RL 标签或漂亮榜单替代工程判断。
