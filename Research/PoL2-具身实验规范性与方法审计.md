# PoL2 具身治理实验：规范性、合理性与研究深度审计

**审计日期：** 2026-10-24
**审计范围：** 有限域动作门检查、MuJoCo Panda 配对演示、授权撤回故障注入及其结论措辞
**判断：** 可作为工程机制演示对外说明；若将其表述为 PoL2 理论效应、机器人策略效应或统计性安全结论，则需要补充实验。

## 一、审计结论

现有实验提出了一个可检验的窄问题：结构化任务授权为 `DENIED` 或 `UNKNOWN` 时，动作门能否阻止一次物体转移，同时不阻止一个明确获准的转移。仿真结果与这个问题对齐，且授权撤回实验揭示了一个真实的闭环缺口：放置前才发现撤回会令机器人停在仍夹持物体的中间状态。该失败结果具有研究价值，因为它说明“拒绝后续动作”不等于“进入安全状态”。

但当前证据支持的是**特定 PoL2 派生任务契约门在固定 Panda 仿真中的机制可行性**。它尚不足以回答 PoL2 是否改变机器人策略推理、是否优于一般访问控制、或能否在任务和扰动变化时可靠运行。现有报告已声明多项限制；本次审计进一步收紧了“穷举符合规格”“PoL2 派生门有效”及“通用基线失效”等容易被读强的表达。

## 二、逐项审计

| 维度 | 当前设计与证据 | 判断及其对结论的影响 |
|---|---|---|
| 问题定义 | 比较门开/关下的 `GRANTED / DENIED / UNKNOWN` 单物体转移，并测试授权撤回 | 对“门是否拦截这个转移”是合理的机制实验；与“模型是否践行 PoL2”不等价 |
| 规则来源 | 将 EAP 边界/同意、正念、诚实等条款映射为单任务契约；许可为合成结构字段 | 透明且可执行，但构念效度有限；自然语言理解、真实授权凭证、感知不确定性都未覆盖，不能代表完整 PoL2 |
| 2,160 项检查 | 144 个类型状态 × 15 个候选动作子集；测试脚本以内联规则生成期望，再与生产过滤输出比对 | 数量可复算，但没有独立 oracle，两个逻辑副本可能共享同一遗漏；更适合称为有限域实现一致性回归检查，而非独立规格验证或形式证明 |
| 状态域语义 | 轴的笛卡尔积包含逻辑矛盾项。按任务定义，`SOURCE + terminal=true` 与 `TARGET + terminal=false` 各有 18 项，共 36/144 个组合 | 这些是抽象异常输入，可用于检查失败闭合；不能把 144 称为 144 个物理可达状态。建议后续把“可达状态”和“故障/矛盾注入状态”分层报告 |
| 候选集语义 | 若过滤后没有候选动作，函数会显式加入 `wait`，即使输入候选集中没有 `wait` | 这是有意的系统级安全回退，不是候选集交集；规格应明确“治理层可注入非移动回退动作”。在搬运中暂停可能留下悬持状态，故 `wait` 不能自动记为安全终态 |
| Panda 对照 | 同一固定场景，门开/关；确定性脚本控制器，每条件一条轨迹 | 门关闭时的越权动作和门开启时的拦截支持该实现案例；同场景配对有利于控制几何差异，但 n=1、无扰动/随机场景，不能估计率、稳定性或泛化 |
| 基线有效性 | 门关闭控制器在 `DENIED / UNKNOWN` 仍执行预设转移 | 这是故意不遵守授权约束的反事实基线，足以验证门的拦截路径；它不是通用机器人系统的代表性基线，也不是学习模型推理失败的证据 |
| 授权撤回 | 抓取前撤回与账本超时被阻断；运输后、放置前撤回阻止放置但物体悬持 | 是有信息量的故障注入，但各条件 n=1；确认“时序相关的恢复缺口”，不能估计其发生率。实验正确保留并披露了这个失败 |
| 运行时检查边界 | 高层准入会检查规范化对象/目标、授权、新鲜度和源位；执行器再次读取权限并检查源位；目前任务接口固定对象、目标和同步仿真观测 | 当前原型没有在每个物理承诺边界重新验证范围/状态版本，也没有通过异步过期观测注入测试。固定同步任务下未显示该缺陷导致结果错误；扩展至真实异步系统前必须明确版本绑定与提交点检查 |
| PoL2 特异性 | 当前规则与通用 ACL / runtime shield 有重合，未做同规则对照 | 无法把“PoL2 的增量贡献”与“明确授权 + fail-closed 门”的一般贡献分开。若两种 shield 执行规则完全一样，拦截率不会识别 PoL2 特异性 |
| 学习与推理效应 | 此组 MuJoCo 轨迹使用脚本控制器；没有比较策略训练前后，也未测过滤前的模型原始提议 | 不支持“机器人学会/践行 PoL2”。需要把策略层效应与屏蔽层效应分开设计与报告 |

## 三、现阶段允许与不允许的表述

**可以表述：**

- 在给定的结构化任务契约、固定 MuJoCo Panda 场景和确定性脚本控制器下，显式动作门拦截了 `DENIED / UNKNOWN` 两种合成权限条件下的转移动作，并保留了这一个获准转移。
- 现有有限域检查未发现过滤器输出与测试脚本内联期望规则不一致；这是代码回归证据，不是独立形式验证。
- 授权撤回实验发现，执行中较晚检查可以留下“仍夹持物体”的部分状态；因此需要设计并验证中止/恢复策略。

**当前不能表述：**

- PoL2 完整理论已经得到验证，或模型已内化 PoL2。
- PoL2 优于常规权限控制或 runtime shielding。
- 机器人在多场景、随机扰动或真实硬件上具备统计意义上的安全性。
- 2,160 项结果证明规格本身正确、完整，或 144 项均为物理可达状态。

## 四、建议的扩展路线

### 阶段 A：把“规格一致”变成独立可核验

1. 冻结一个带版本和散列值的机器可读动作契约，明确状态、授权范围、动作前置条件、终态及恢复动作的语义。
2. 使用与生产过滤器不同的实现路径作为 oracle，例如从声明式规格生成参考集合，或使用独立模型检查器；不要把同一段 Python 条件复制为期望值。
3. 把输入拆成两套：任务模型下可达的合法状态；明确标记的矛盾、过期、缺字段及边界故障注入状态。报告每套域大小和结果。
4. 在边界值和授权撤回状态上做属性测试与 mutation testing：故意移除一个权限/范围/时效判断，测试流程应能检出变异。否则“全通过”仍可能只是弱测试。

### 阶段 B：验证闭环，而非单点拒绝

在 `approach / before_grasp / after_grasp / before_lift / before_transport / before_place / after_release` 等物理承诺点注入撤回；另注入权限读取超时、旧 revision、对象/目标范围变化、重复/乱序事件与控制器动作失败。每一故障至少记录：是否发出不允许的执行命令、物体是否被移动、是否仍被夹持、是否稳定支撑、是否碰撞、是否到达安全终态、恢复动作是否成功以及任务是否误报完成。

对撤回后的恢复规则单独冻结。可选策略（放回源位、放在最近稳定支撑面、受限夹持保持）必须用几何/接触状态与控制器约束判断，不由模型临场自由生成。当前“悬持”结果不能靠报告中的建议当作已解决能力。

### 阶段 C：从演示扩展到可重复的仿真评估

- 先做多种子/多布局先导，估计基线事件率、种子间相关性、场景难度和主要指标方差；据此进行功效或精度分析后再锁定确认性样本量。任意指定一个重复数并不能自动构成充分样本。
- 对每个场景种子采用配对条件（同一初始状态、扰动、任务；条件顺序随机化），但统计单位应是独立场景/种子，而不是同一场景里高度相关的控制步数。
- 至少包含：授权且可完成、拒绝、未知、授权范围不匹配、终态已满足、状态过期、执行中撤回、感知/账本故障。加入不同物体位姿、障碍物和目标布局；保留按场景族隔离的未见测试集。
- 预先定义主指标：未授权执行比例（越低越好）、授权任务成功率/完成时间、拒绝情况下的安全终态率、撤回后恢复成功率及约束违反数。报告分母、场景级不确定区间和所有失败类型；授权任务的完成率不能被“安全地停住”替代。
- 确认性轮次开始前冻结协议、代码/策略哈希、排除规则、主终点和分析方法。探索性结果可以继续迭代，但不可与保留确认集反复混用。

### 阶段 D：单独识别 PoL2 对模型决策的影响

固定同一底座模型、数据量、训练步数、提示长度/模板、解码参数和任务暴露；比较通用决策训练、中性类型决策训练、PoL2 类型决策训练。对每个原始输入保存**盾牌前**候选动作及理由结构，盾牌后输出与真实执行结果另列。训练、开发、校准和测试按任务/场景族隔离；不把规则生成器产生的近重复样本随机拆到训练与测试两侧。

主要模型端点应测模型在过滤前是否：在拒绝/未知/越界时自行不提议转移；在获准且有用时提出可执行动作；在已完成时正确停止；在状态未知时选择有信息增益且低承诺的动作。报告违反率、合法任务效用、拒绝质量、校准/选择性风险和延迟。硬门可以保留为执行保护，但它的拦截贡献不能冒充策略学会规则。

若要识别 PoL2 的独特贡献，先把 PoL2 文字原则预先映射成通用 ACL 没有的可观测规则（例如某项明确的边界、诚实或恢复义务），并提供可区分的反事实任务。如果映射后与通用 ACL 的动作集合完全相同，实验最多说明 PoL2 能指导出一套可执行授权契约，不能说明该契约在机器人行为上优于一般盾牌。

## 五、建议的下一轮优先级

1. **先补撤回安全恢复**：上一轮已经观察到悬持中间态，优先实现一个保守、可审计的恢复控制器，并用状态谓词验证恢复成功/失败边界。
2. **独立规格 oracle + 故障注入**：将“实现与自己规则吻合”提升为可独立复核的有限域验证，并覆盖版本过期、范围变化和提交边界。
3. **扩展场景并做先导功效分析**：确定合理的场景种子量、指标与不确定性口径后再跑确认性批次。
4. **最后测模型内化**：先冻结三臂策略实验，记录盾牌前提议；不把安全门的确定性拦截写成模型本身的行为改变。
