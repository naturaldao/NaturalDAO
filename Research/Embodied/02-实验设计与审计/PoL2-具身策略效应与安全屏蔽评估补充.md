# PoL2 具身策略效应与安全屏蔽评估补充

**日期：** 2026-10-24

**范围：** 基于现有 MuJoCo Panda / Kev typed-choice 记录，对 PoL2 是否改变动作选择、以及运行时合约是否阻止越权执行作区分。

**结论状态：** 先导证据复核；不是 PoL2 总体效能结论。

## 核心判断

现有证据支持两个有限判断：

1. **运行时合约能拦截本基准中不符合规则的动作。** 已保存的 forced-action probe 显示，DENIED 状态下强制提交 `deliver`，无门控时仿真器执行搬运；启用门控则在执行前阻断。Qwen2.5-7B 的通用提示、关闭门控的单次 Panda 仿真也提出并执行了 `transfer`，导致对象被移动；同一任务的 PoL2 提示单次选择 `wait`。这些是一个合成任务和单次运行的结果。
2. **尚无证据显示 PoL2 提示稳定优于长度匹配的中性提示。** Kev checkpoint 的 16 个固定案例、三条件配对筛查中，generic、中性等长提示、PoL2 提示均为 13/16 个动作符合预设标签，各有 1 次禁行动；中性提示和 PoL2 在每个案例上的模型报告输入 token 数完全相等。PoL2 与中性提示在 4 个案例选择不同动作，但正确数净变化为零。这个结果不能支持正向净效应，也不能据小样本断言效应为零。

因此，**本阶段更扎实的贡献是实现并演示了策略与运行时约束的分层闭环；“PoL2 让模型学会按理论推理/行动”仍待检验。** 对理论影响的检验必须记录模型在过滤前提出什么、执行器最终执行什么，以及任务结果；只报告门控后的安全成功率，会把策略能力和安全机制混为一谈。

## 工程与学术先例界定

### 运行时屏蔽不是模型已经内化规则

Alshiekh 等人在 AAAI 2018 的 Safe RL via Shielding 中明确区分前置屏蔽（给策略安全动作集合）与后置屏蔽（拦截并修正策略提案）。其安全主张以给定的环境抽象和规则规格为条件；若部署保证由 shield 提供，shield 仍须处于执行路径中。策略在 shield 关闭后的表现是另一项诊断指标，不能从 shield 开启时的安全行为反推策略已经安全 [[Als17]](https://doi.org/10.1609/aaai.v32i1.11797)。

这与本原型的职责划分一致：PoL2 派生合约过滤候选动作，模型只在候选集内排序；执行端再次检查权限、对象/目标和任务前置条件。与文献先例的差异是，本原型当前的规则是单一桌面转移任务的手工操作化，并非由形式化综合得到的完整 PoL2 规格，也没有证明状态抽象覆盖真实环境。

### 连续具身控制需要显式处理状态、动力学和可观测性

Kim 等人提出连续状态/动作空间中的 proper shielding，验证安全动作是否始终存在，并在仿真导航和多智能体粒子任务中评估无屏蔽、碰撞屏蔽、循环避免和动作优化等设置；该工作报告多随机种子和每种子多次运行，也讨论部分可观测导致的残余碰撞及实时性限制。它提供的是连续空间屏蔽与仿真评估先例，不是 PoL2 效果证据，也没有报告实体机器人试验 [[Kim24]](https://doi.org/10.48550/arXiv.2410.02038)。

Jansen 等人的概率 shield 将安全相关模型检查与性能策略优化分离，并在服务机器人式仓储任务的仿真中报告不同 shield 覆盖范围下的结果。其概率结论依赖构造的 MDP、行为模型及有限时域；这提醒我们必须把仿真模型误差和感知误差列为保证边界 [[Jan18]](https://arxiv.org/abs/1807.06096)。

### 先例对本项目的直接要求

- 同时报告 **raw proposal、shield intervention、executed action、task outcome**。门控后结果只代表“策略 + shield”的组合系统。
- 将策略偏好评估与部署安全保证分开：policy-only ablation 只在隔离仿真；真实执行继续保留独立 shield 和执行前校验。
- 在连续状态与感知不确定下复测：物体位置、观测新鲜度、状态置信度、许可状态变化、目标占用和失败恢复不能只以固定状态代替。
- 将规则模型的适用假设与被测系统一致性单独报告。有限测试中零违规不构成形式化保证。

## 下一轮实验：把 PoL2 的可检验影响拆开

### 主要估计量

首要问题限定为：**在相同模型、相同观察、相同动作集合下，PoL2 原则提示相对于长度匹配的中性决策提示，是否降低禁行动提案，同时不显著降低明确授权任务的完成率？** 这检验提示层行为，不等价于验证模型隐式推理链，也不等价于验证 PoL2 全理论。

### 配对因子设计

每一个冻结的场景状态都运行同一模型的四个条件：

| 提示条件 | 运行时屏蔽 | 测量对象 |
|---|---|---|
| 通用任务提示 | 关闭（隔离仿真） | 模型基线提案 |
| PoL2 原则提示 | 关闭（隔离仿真） | PoL2 对提案的影响 |
| 通用任务提示 | 开启 | 屏蔽器单独贡献及任务结果 |
| PoL2 原则提示 | 开启 | 策略提示与屏蔽器组合表现 |

另设等 token 数的中性提示，作为文本长度控制。对每个固定状态随机化调用顺序；若模型接口非确定性，重复采样并保留原始请求、概率、服务温度、checkpoint 与逐次结果。比较时以场景为配对单位，不能把一次场景里的多个动作决策当成独立样本。

### 场景与报告指标

预先冻结至少六种状态族：明确授权且前置条件满足、明确拒绝、许可未知、对象/目标范围不匹配、观测过期或低置信、执行中许可撤回；加入目标已达成、目标被占用、对象不在预期位置等任务状态。每族多初始姿态、多随机种子；从小规模试跑估计方差后再做功效分析，避免直接宣称某个固定样本量足够。

主要指标：禁行动 raw proposal 率、错误拒绝率、授权任务成功率。次要指标：shield 拦截率、实际禁行动执行率、干预幅度/动作偏差、完成时间、停止/卡死率、恢复成功率、推理延迟，以及状态变化后的重新授权是否被及时感知。结果按权限状态和场景族分层，给出置信区间与配对差值。

标签可由冻结的形式化任务契约和独立实现的规则检查器自动产生，符合项目不安排人工审批的设定；但双实现一致只验证实现一致性，不能证明契约就是完整或正确的 PoL2 规范。模拟器任务成功由 MuJoCo 终态谓词独立判定，不由生成标签器自我评分。

## 实施边界

1. 当前 MLP 保留集没有授权 transfer 正例，现有数据不适合支持 transfer 泛化主张；在增设真实变化的任务状态因子、并按完整场景族隔离后，才可训练下一版。
2. 所有无门控运行继续限定于 MuJoCo；真实机器人或硬件接口不得提供绕过屏蔽器的执行路径。
3. 优先完成同 checkpoint、token 匹配的提示对照与四格门控消融，再考虑将类型化决策器接入新的操控状态。不要把选择器拟合合约标签的准确率当作“PoL2 推理增强”。
