MemT-1.0：把“历史”写进模型内部的
记忆原生基础模型

一句话：MemT-1.0 在冻结的 MoE 骨干（Qwen3.6-35B-A3B / DeepSeek-V4-Flash）里，给选定层并联一个可训练的记忆块。每轮对话结束时，它用 gated delta rule 把这一轮的 token 逐个写进一块固定大小的状态矩阵。之后推理不再读历史原文，只读这块状态（Nano 40 MiB / Flash 1280 MiB）。

01

它想解决什么问题

让 LLM “记住”一段很长的历史，今天主要有三条路。三条路各有一笔账算不过来，MemT 想走第四条。

① 全上下文：每次重读全部历史

质量最好（Table 2 中 Full Context 平均 65.0–66.3），但 prefill 成本和延迟随历史增长。论文 Fig.8：128K 历史时端到端耗时 30.07 s，256K 时 94.47 s。窗口用完就只能截断（BEAM 被左截断到 256K）。

② KV cache 线性增长

缓存历史的 KV 可以省掉重算，但显存和存储与 token 数成正比。按 Qwen3.6-35B-A3B 的公开结构推算：60 MiB + 20 KiB × token，128K 时约 2.6 GiB/轨迹，256K 时 5.061 GiB（论文 Fig.3）。

③ RAG / 外挂记忆

把历史切块存进向量库或记忆系统（MemOS、Mem0…），用时检索。存储小、质量高（MemOS 平均 68.5–68.6，是全表最强），但会漏检，记忆也不在模型“里面”。128K 时 DenseRAG 只占约 25.5 MiB。

④ 参数化记忆：写进权重

用 LoRA、超网络等把历史写进参数（Temp-LoRA、Doc-to-LoRA…）。问题在于权重更新是全局的：不同用户、不同会话难以隔离，写入要靠训练。Temp-LoRA 在 128K 时端到端耗时 700.8 s。

MemT 的赌注：固定大小的“每轨迹状态”

MemT 属于第 ④ 类里的“状态式”分支。记忆参数 φ 离线训练，在线时冻结；每条轨迹（会话）只携带一块独立的状态矩阵 M_t，写入用前向计算，不需要训练。因此 M_t 天然按会话隔离，大小恒定，可以快照、恢复、迁移。代价是容量固定，细节会被压缩。

02

架构：冻结骨干 + 并联记忆块

在选定的注意力层，记忆注意力与原注意力并行计算，两路输出相加：A = A_ori + A_mem。骨干的 Pre/Post-Attention 和 Attention 都保持不变。鼠标悬停（或点按）图中模块可查看说明。

悬停查看模块说明

把鼠标移到左图任一模块（手机上点按）。绿色实线是生成时的读路径，紫色虚线是轮末写路径。

核心思想：骨干完全不动，只在 Nano 的 10 个全注意力层（3, 7, …, 39）、Flash 的 20 层（4, 6, …, 42）各并联一个记忆块。记忆块读的是一块每条轨迹各自持有的矩阵，而不是历史 token。

Local Memory 与 Hyper Memory

Local Memory（动态状态 Mt）

  • 形状 H_kv × d_k × d_v，每层一块；Nano 10 层 × 16 × 256 × 256 = 10,485,760 元素，Flash 20 × 64 × 512 × 512 = 335,544,320 元素。
  • 每条新轨迹清零；快照强制 FP32（40 MiB / 1280 MiB），格式 memt-memory-v1，带 identity 哈希校验。
  • 相对前作 Metis：去掉了 normalization 向量，改为多通道（多头）。

Hyper Memory（可训练参数 φ）

  • Q/K/V 投影 W̃Q, W̃K, W̃V；erase 门 Wβ、write 门 Wω；遗忘门 (Wf, Wλ, bλ, s)；输出门 (Wg/d, Wg/u)。
  • Nano 450,931,360 个参数，Flash 3,608,608,000 个。按附录 B 的几何重算，与 Table 6 逐位相等。
  • Flash 用低秩分组投影（q 1024 瓶颈、8 组 KV、四个 rank-512 门）。

读写时序：生成期间只读，轮末才写

Turn t · prefill + decode

本步的所有 query 都读入口快照 Mt。逐 token 生成时记忆不更新。我们在 HF 代码上实测：prefill 1 次、decode 5 次，全部 commit=False，生成后状态与生成前完全相等。

轮末 commit

只有生成正常结束（末 token 为 EOS）才提交：把 S_t = X_t‖Y_t 逐 token 写入，得到 Mt+1。被长度截断的 turn 不写入。

Turn t+1

读 Mt+1。所以本轮的新信息要到下一轮才可见。旧轮次的原文不再进 prompt：实测 input_tokens 从 81 降到 39。

  • system prompt 和 tools 永远不写入记忆；思考内容（<think>）会写入。
  • 用 transformers 标准的 pipeline 或普通 generate 时，记忆分支输出为 0，模型退化成原骨干。必须用远程代码提供的 Session API（create_session / chat(enable_memory=True)）。来源：docs/analysis/05 §2.4–2.5。

论文公式（Stable GDN-2，对第 l 层、第 h 通道）

它和 KDA / 线性注意力是什么关系？

先说结论：MemT 的记忆更新不是新算子，和 KDA（Kimi Linear 的门控线性注意力层）同属 gated delta rule 家族。论文写的是 Gated DeltaNet-2（GDN-2）；社区 llama.cpp 补丁的 commit 原文就是 commit pass on ggml_gated_delta_net (KDA gate, beta = 1)，实现层直接复用 KDA 门控的 kernel。真正的区别在角色与生命周期，不在更新公式。

维度KDA（Kimi Linear 的线性注意力层）MemT 原生记忆
角色骨干里的 token mixer，与全注意力混合（3:1），替换注意力冻结骨干上的并联旁路，加到 full-attention 层输出
更新时机每个 token 前向中更新只在轮末 commit 用整轮 token 更新；生成时读快照
生命周期一次请求/序列内，结束即丢跨轮/跨请求持久，按会话隔离，可 save/restore/erase
训练与全模型端到端预训练骨干冻结，只训记忆参数（Nano 451M=1.3%），full-context 教师蒸馏
读出q·S 进残差流R=Q·M/√d → RMSNorm → SoftCapSiLU 门控 → 加回注意力输出
状态每层 H·dk·dv，per-sequence每会话 10.5M 元素（40 MiB）/ 336M（1280 MiB）
衰减预训练学得的门decay bias 显式初始化：Nano 半衰期 [2048, 32768] token；Flash [128, 32768]

MemT 相对 KDA 的真优势

  • 部署形态：跨会话持久、事务式 commit/read、快照、会话隔离、即插即用（冻结骨干）。KDA 的状态不跨请求。
  • 数值稳定：SGDN-2 的对称化 erase 让 (I−UᵀU) 非扩张（谱范数 ≤1；我们复现 1.1512 vs 上界 2/√3=1.1547），因此能用 2k–32k 的长半衰期；朴素 GDN-2 在半衰期 >6.2 token 时就指数爆炸（fp32 388 token 内溢出）。

没有优势的地方

  • 记忆容量/保真度：同权重实测 N50≈10 条高熵事实；20 条事实写 ~275 token 无关文本就回到随机；同权重 full-context 90–100%、RAG 100%。
  • KDA 是端到端训练的主干组件，能与全注意力混合；MemT 是冻结骨干上的旁路，读出余量小（近 tie 会翻转）。优势是“持久”，不是“记得多”。

术语：Metis、MoS、KDA

Metis（前作）

MemTensor 2026-07 的记忆基础模型（arXiv:2607.26760）：“dynamic local memory + trainable hyper memory”，写入时做 token selection 与 key normalization。MemT-1.0 保留 local/hyper 两层，去掉 token selection 与 key normalization，改为 GDN-2 的 token 级更新 + 多通道。

审计发现：附录 E.2 把 Metis 的架构当成 MemT-Nano 的训练细节来写；Fig.15 中 Metis 的 pass³ 在 4 个 agentic 设定里都高于 MemT（前作反超，被放在附录）。

MoS（Mixture-of-Storage）

论文提出的容量扩展机制：把一个记忆块扩成 E 个 expert（状态 E×Hkv×dk×dv），两个稠密 router 共享可训练地址矩阵 C：αu 决定读权重，αs 缩放写入的 β/ω（λ 不缩放）。

但发布模型都是 E=1（Table 6 原文 “Both use one memory block per selected layer (E=1)”），发布物里没有任何 router/address/expert 张量——头条贡献没有交付；论文自己的 E=2→4 实验也只涨 0.4–2.7 平均分。

KDA（Kimi Delta Attention）

Kimi Linear 的线性注意力层：门控 delta rule + 逐通道对角衰减 + 分块并行；与 MemT 使用的 GDN-2 更新同族。MemT 把同族状态做成跨会话持久、可快照、旁路注入的记忆层，而 KDA 是主干内的 token mixer——这是“记忆层”与“注意力层”的区别。

社区补丁的 kernel 就是 gated_delta_net（KDA gate, beta=1），实现层证据见 docs/data/public/llamacpp_memt_patch.patch:9。

trust_remote_code 的信任成本

加载 HF 版本时你在信任什么

  • 仓库里的 Python 代码，每次加载都会执行。Nano 约 1.1k 行；Flash 约 1.9k 行，而且只加载 tokenizer 也会执行整份 modeling 和 encoding_dsv4.py。
  • 加载那一刻的仓库版本：README 示例没有钉 revision，以后推送的任何代码都会在下次加载时执行（供应链风险，中）。
  • transformers 必须是 5.12.1，依赖其私有接口。
  • 我们挂 PEP 578 audit hook 实测：remote 模块直接触发的事件只有 5 次 import，网络和进程事件为 0。
  • 风险评级：Nano 低，Flash 低–中。前提是钉住 revision，并在本地读过代码。

建议的加载方式

REV = "30fe0b22422c4cc4c87475f98db5c8baa5c1a902"  # 已审读版本
model = AutoModelForCausalLM.from_pretrained(
    "MemTensor/MemT-1.0-Nano", revision=REV, code_revision=REV,
    trust_remote_code=True, dtype=torch.bfloat16)
tok = AutoTokenizer.from_pretrained(
    "MemTensor/MemT-1.0-Nano", revision=REV)  # Nano 的 tokenizer 不需要远程代码

或者先下载 snapshot，diff 审读后从本地目录加载，并设 HF_HUB_OFFLINE=1。SGLang 路径不执行 checkpoint 里的模型代码（强制 trust_remote_code=False），但 Flash 客户端会执行 checkpoint 目录中的 encoding_dsv4.py（H-2）。另外，HF 的 save_state 在 Windows 上必然失败（两处缺陷串联）。

08

我们的独立实验

本机没有能跑官方 BF16 推理的 GPU（Nano 需要 2×GPU 和 70GB 权重，本机只有 Tesla T10 16GB），训练所需的代码和数据也没有公开。所以我们选了四条能独立检验的路线。下面先介绍方法，再给结果。

① 官方代码 tiny-config 跨实现一致性

用 HF 远程代码搭一个微型 config（hidden 128，2 层 [GDN, full-attn]，4 头，head_dim 32），在 CPU 上真实走 trust_remote_code 加载。逐项对拍：论文公式的 float64 参考实现、HF 实现、SGLang 实现的数学语义。同时验证读写时序、零状态等价、持久化格式和 identity 校验。

前期已完成，详见 docs/analysis/05：state 相对误差 3.1e-7；生成期 6 次记忆调用全部只读；零状态与无状态的 logits 差为 0.0。

② 社区 GGUF Q4 + CPU：真实权重黑盒实验

用社区的 MemT-1.0-Nano Q4_K_M GGUF（21.6GB）和 llama.cpp MemT 补丁，在 WSL（46GB RAM）里纯 CPU 推理。计划测量：事实容量（准确率 vs 事实数 N）、干扰/遗忘（准确率 vs 干扰段数 M）、长历史针、快照持久化、效率（memory 模式 vs full-context）。用固定模板加关键词匹配判分。

这是 Q4 量化、CPU、社区补丁下的黑盒行为，不等于官方 BF16 数值。

③ Mini-MemT：迷你 scaling 实验

在 CPU 上实现一个与论文一致的迷你 Native Memory Block（4 层，d=128，GDN-2 更新 + 读路径 + 输出门），在合成的“多轮事实注入 + 后续查询”任务上，控制状态规模（dk、头数、层数）、历史长度、条目数和干扰数。尝试拟合准确率与 log(状态元素数) 的关系；最终没有拿到可外推的幂律，因此不与 Nano(10M) / Flash(336M) 做外推对照。

论文本身没有拟合任何幂律，这是对 Fig.6/Fig.7 的独立补充。

④ llama.cpp 补丁审计

逐行核对社区补丁的更新公式与论文是否一致：u = k·√sigmoid(b)，v = ω⊙V，g = softplus，beta=1 的 delta rule。确认它能作为真实权重黑盒实验的载体，并检查转换出的 GGUF 能否通过 sanity demo。

前期结论：更新公式与论文一致（docs/reports/phase1-repro-audit.md §3）。

判断与跟进建议

一句话：真东西，但被包装得比实际更大。这是一次认真的、可审计的规模化工程，不是记忆的新范式。

含金量在哪（站得住的）

  • 权重与架构是真的：记忆参数和状态大小与论文逐位相等；三套实现与公式一致（相对误差 3e-7）。
  • 长历史的存储和延迟优势是结构性的：状态固定为 40 MiB / 1280 MiB，TTFT 平坦（约 104–112 ms），128K 以上端到端加速 1.86–3.99×。这是机制决定的，可以外推。
  • 不读原文也能恢复 71–78% 的全上下文质量，这是全文最有信息量的结果。
  • 消融清晰：后训练 +10.7，token 级更新 +6.0。
  • 工程质量高：槽位池、事务式 commit/publish、快照身份校验、Triton/WY 分块核、SGLang 深度集成。

被高估的（要打折的）

  • “超过参数记忆基线”：对手多为 4–8B、截断历史的模型。
  • “与 RAG 相当”：实际落后 6.7–21.5 分，在 LME 和 BEAM 上落后 35–49 分。
  • MoS 作为头条贡献，没有在发布模型中出现。
  • “通用能力基本保持”：依赖很轻的噪声设定。相对干净骨干，Nano 的 GPQA 和 LCB 各掉 5 分以上。
  • agentic 提升约 3pp，在噪声内；配置在测试集上挑选。
  • 媒体说法：“KV 完全去除”“显存 5.06GB→40MB”“首个开源记忆原生”都失实。

研究者

值得跟进 ★★★★
